# Runbook: pipeline alarms (dev/observability)

Every alarm notifies `procurelake-dev-pipeline-alerts` on ALARM and on OK. Start from the
dashboard `procurelake-dev-operations`.

| Alarm | Means | First step |
|---|---|---|
| `procurelake-dev-sfn-cdc-processing-failed` | A CDC run failed, timed out or was aborted | Step Functions execution history: which state failed. CDC apply: Glue run logs. A held lease clears itself after its TTL (ADR 0028) |
| `procurelake-dev-sfn-dbt-transformation-failed` | dbt failed, or the tenant access check after it failed. Started by `cdc_processing` (only the models downstream of queued Silver tables) or by the daily full build at 07:40 Toronto (ADR 0050) | Container exit code and `dbt/runs/<run id>/run_results.json` in the artifacts bucket. If the access check failed, see below. A failed CDC build keeps its tables queued (`gold#cdc` / `pending` in the checkpoint table), so the next run builds them again; an invalid queue entry fails the runner before dbt starts. Two builds at once (daily build during a CDC session) can fail on an Iceberg commit conflict: rerun, or wait for the next run |
| `procurelake-dev-sfn-tenant-access-check-failed` | A tenant lost access to a mart, or can see another tenant's rows | `ForeignRowsVisible`: find the extra Lake Formation grant and revoke it (`list-permissions` on the table). Access lost: a mart was dropped (full refresh), so re-apply `dev/security` with `-parallelism=1` (ADR 0030) |
| `procurelake-dev-sfn-tenant-exports-failed` | A daily export failed | Execution history: Athena error in `Unload`, or S3 in `WriteManifest`. Rerun with `make tenant-exports-run` (each run writes a new `run=` prefix) |
| `procurelake-dev-cdc-source-to-silver-latency` | A CDC batch reached Silver more than 15 min after its oldest source commit | After a stall, expected once for the backlog (see `cdc-dms-stall.md`). Otherwise slow Glue starts or a long-held lease. **Its OK only means time passed** (ADR 0050): with no newer batch it clears by itself about 15 minutes after a late one (Week 8 drill). An OK email does not mean a later batch arrived or was on time; check the `SourceToSilverSeconds` datapoints (dashboard "CDC" widgets) after the alarm |
| `procurelake-dev-cdc-rejected` / `-held` | CDC events were quarantined, or keys are held at an older version | Quarantine prefix `quarantine/silver_cdc/<table>/batch_id=…/` lists each event with its reasons. Fix the source row; the next change supersedes the held version |
| `procurelake-dev-cdc-blocked` | A batch exceeded the rejection ratio and was not applied | As above. The batch is retried on every run until the files are fixed or the gate is changed (ADR 0028) |
| `procurelake-dev-cdc-dms-source-latency` (dev/cdc) | DMS is running but not capturing (latency over 5 min). Missing data is not an alarm (ADR 0050): INSUFFICIENT_DATA means no metrics, at stack creation or because the task stopped | `cdc-dms-stall.md` |
| "ALARM … DMS replication task stopped or failed" (EventBridge rule `procurelake-dev-cdc-dms-task-stopped`, dev/cdc) | The task stopped or failed: nothing reaches Bronze, Silver or Gold | `cdc-dms-stall.md` |
| `procurelake-dev-sfn-batch-ingestion-failed` (and the "batch ingestion failed" SNS message) | An ingestion task did not exit 0, or the USAspending Silver step failed | Execution history: which state failed. `RunIngestion`: the batch manifest in `pipeline_manifests/` records why (USAspending: the API blocks a client for about 5 minutes after about 250 quick requests, so requests are paced; pages after the first are requested by keyset, so a day over 50,000 records no longer hits the API's HTTP 422 cap, ADR 0046; a keyset cursor that disagrees with the API or does not advance fails the batch. The next run, or the next weekly re-sweep, collects a failed day again). `ApplyReferenceToSilver`: the run summary under `pipeline_runs/silver/usaspending/reference/` lists `blocked_batch_ids`; each blocked batch's rejected records and reasons are under `quarantine/silver/spending_by_award/batch_id=…/`. Rerun with `make reference-silver-run`; it applies only batches not yet applied (ADR 0044) |
| `procurelake-dev-sfn-document-intelligence-failed` (and the "contract extraction failed" SNS message) | A document's extraction did not exit 0 or did not start, after its retries | Execution history: the input names the manifest key or document id. Task log `/procurelake/procurelake-dev-task-runner`: `AccessDeniedException … not available for this account` means the Bedrock quota is still 0 (ADR 0045); a throttling error means several documents landed together. The audit prefix `audit/ai_extraction/document_id=…/` holds the request and the error. Rerun with `make document-intelligence-run DOC=<id>`; a document already extracted from the same PDF, prompt and schema is skipped |
